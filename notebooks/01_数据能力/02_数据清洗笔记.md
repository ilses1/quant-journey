## 一、5 类脏数据怎么处理

| 问题 | 检测方法 | 处理方式 |
|------|----------|----------|
| 缺失值 | `df.isna().sum()` | 价格 `ffill()`、成交量填 0、收益首日 NaN 保留 |
| 异常值（涨跌幅 > 11%） | 分组 `pct_change()` 后 `abs() > 0.11` | 标记 `is_outlier` + 剔除 |
| 停牌（成交量 0/NaN） | `df['volume'] <= 0` | 标记 `is_suspended`，回测中跳过而非删除 |
| 复权不一致 | 单日跳空超涨跌停 | 回到数据源统一复权口径（前复权） |
| 重复数据 | `df.duplicated(subset=['code','date'])` | `drop_duplicates(keep='last')` |

**核心区分**：停牌是"合法状态"用**标记**；异常值是"错误数据"用**剔除**。二者不能混为一谈。

## 二、清洗顺序（重要）

处理顺序有讲究，搞反了会出错：

```
1. 规整日期、排序    ← date 先转 datetime，否则按时间运算全错
2. 去重             ← 先删重复，避免重复行干扰后续统计
3. 填充缺失值        ← 价格 ffill、成交量填 0
4. 标记停牌/异常     ← 最后打标，因为填充会改变"哪些算缺失"的判断
5. 重算派生字段      ← return/nav 要基于干净价格重算
```

## 三、存储方案怎么选

| 规模 | 方案 | 说明 |
|------|------|------|
| < 1GB | CSV / **Parquet** | Parquet 更快更小还保类型，首选；需 `pip install pyarrow` |
| 1~10GB | SQLite | 单文件数据库，无需配置 |
| > 10GB | PostgreSQL / ClickHouse | 大规模、需要并发 |
| 盘中实时 | Redis / InfluxDB | 时序、高频 |

## 四、增量更新原则

- **追加而非全量覆盖**：只拉最后交易日之后的新数据，`pd.concat` 拼到存量上
- **合并后去重**：`drop_duplicates(subset=['code','date'], keep='last')`，防止边界日期重叠
- **记录最后交易日**：下次增量从 `date.max()` 之后继续拉

## 五、关键代码记忆点

```python
# 涨跌幅必须按股票分组算（不同股票间价格差异不是涨跌幅）
pct = df.groupby("code")["close"].pct_change()
outliers = pct.abs() > 0.11

# 停牌 = 没有成交（量 0 或 NaN）
suspended = (df["volume"].isna()) | (df["volume"] <= 0)

# 缺失填充按列类型区分：价格 ffill、成交量填 0
df[["open","high","low","close"]] = df[["open","high","low","close"]].ffill()
df["volume"] = df["volume"].fillna(0.0)

# 去重：同一只股票同一天只留最新一行
df.drop_duplicates(subset=["code", "date"], keep="last")
```

## 六、踩过的坑

1. **CSV 读回来 date 变成字符串** —— 必须先 `pd.to_datetime`，否则 `groupby().diff()` 报 "str 不能相减"。
2. **把停牌当错误删掉** —— 停牌日是合法交易日，删了会导致收益计算错位（把两个不相邻交易日当成相邻）。正确做法是标记后回测时跳过。
3. **清洗后忘记重算 return/nav** —— 填充/剔除改变了价格序列，派生字段要基于干净价重算，否则拿到的是旧值。
4. **没装 pyarrow 就 `to_parquet`** —— 会报 `ImportError`，用 `try/except` 回退 CSV 或先 `pip install pyarrow`。
